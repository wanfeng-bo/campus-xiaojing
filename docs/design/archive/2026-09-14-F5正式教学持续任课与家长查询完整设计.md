# F5正式教学、持续任课与家长查询完整设计





## 1. 这阶段交付什么

F5把学校已经确定的教学安排变成可维护、可查询、有来源和历史的正式事实。家长能问孩子由谁教、学什么、如何联系；教师能问自己的任教和教研关系；获准维护人员能登记、更换、结束或纠正安排。即使没有选课、课表、考勤模块，这些查询也能成立。

**最常用的一条链路：** 家长登录并选定孩子 → 学校核实当前访问资格 → 找到该孩子在所问时点的正式教学关系 → 找到课程、学科及任课教师 → 返回简洁答案及获准官方渠道。模型理解“数学谁教”“下学期还是他吗”等说法，领域能力负责找准正式关系，不在内核写问法路由。

另一条独立链路是家长查“校长是谁”：按当前家校关系所在学校查询正式领导职务目录，不要求领导教这个孩子，不局限孩子所在校区。它属于现有学校目录的家长读取补接，与F5教学事实分开拥有、一起列入本次待审交付。

| 使用者 | 能完成的事情 | 默认看到什么 |
|---|---|---|
| 家长 | 查询自己孩子的课程、相关老师、官方渠道、当前／获准历史／已登记未来；提交资料报错；查本校领导 | 直接回答人、课和必要时间；多门课或共同任教分清对应关系。重要冲突、缺失、权限限制明说 |
| 普通教职工 | 在已授结构读取范围内查课程、开课、任教和教研范围 | 名称和正式关系；不自动显示学生明细 |
| 任课教师 | 获授用途后查本人教什么、教哪些班／群体；获授学生工作用途后查对应成员 | 本人的任课清单；学生名单与其他资料分开核权 |
| 教研／备课成员 | 获授用途后查本人所属组织、组织正式覆盖的学科和年级 | 组织、成员身份和适用范围；不是一张自动拥有学生权限的名单 |
| 获准维护者 | 录入、批量调整、预览、正式确认、查原回执、纠错和读回 | 可读的完整差异和影响对象；技术引用、版本和追踪信息放维护详情 |

不建设学生端、聊天建群、通知、选课报名、自动分层或分班、排课求解、逐节课表、临时调代课、成绩、考勤、通用教学流程或新权限平台。已有永久排除边界（历史文档引用）完整适用，不另写缩减版。

## 3. 对象分工与唯一事实权威

下列是产品语义，不等于同样数量的新表、页面或服务。推荐继续使用现有规范根／版本／引用能力，并为教学建立有限、严格的类型和关系约束。

| 对象 | 含义及最小内容 | 身份、时间和约束 |
|---|---|---|
| 学科 | 学校正式学科名、稳定来源、别名、明确适用学段 | 同名不自动合并；学校决定数学跨学段是同一学科还是不同对象 |
| 课程目录 | 学校确认的课程、正式名称、课程性质及必要适用说明 | “数学”学科不等于每门数学课程；名称变化不自动新建，实质新课程不冒用旧身份 |
| 课程—学科关系 | 一门课程涉及哪些学科，可写明主关联或内容范围 | 允许一课多学科、同学科多课；不只取第一学科，也不自动把所有老师称作每个学科的负责老师 |
| 正式开课 | 某门课程面向明确对象的持续教学安排、有效时间和状态 | 有自己的稳定身份；不是“课程＋学期”的年度副本，也不是某天某节课 |
| 授课对象与成员来源 | 每项开课的一段来源定义：A行政班，或B独立教学群体 | 来源本身有历史；相同时段只有一种有效权威。基本对象为一个班或一个群体，跨班合成用B |
| 独立教学群体 | 学校正式确定的一组教学对象、名称、用途和生命周期 | 复用组织稳定身份及独立教学档案，可供多项开课共用；不为普通整班强建教学群体 |
| 独立教学成员 | 学生、对应本校在校关系、所属群体及有效期间 | 可多群体并存；同一群体同一学生同期不得用重复来源记录两次入组 |
| 正式任教 | 正式任职与开课的关系、主讲／共同任教等角色、必要职责内容、起止时间 | 可无预定截止；一人跨课跨校区合法，多人任教按学校人数规则，不因无课表猜排课冲突 |
| 教研／备课适用关系 | 既有组织与学科、学段、明确年级或学年年级、学期等的现实业务关系 | 成员沿原组织事实；适用范围不是授权范围，不从组名猜，不自动包括下级组织 |

对跨学科课程，任教默认表示负责这门课；只有学校正式明确教师负责其中某学科部分时才记录该限定，且限定必须属于课程当期的正式学科集合。问孩子数学老师时，可以回答“综合探究课涉及数学，由陈老师、李老师共同任教”；不能擅自拆成陈只教数学、李只教物理。

正式开课可以已经确定，而教师资料尚未录入或岗位正式空缺。此时不伪造任教记录，也不因查不到老师否定开课；空缺由对应岗位、开课及期间的正式声明表达。推荐“一名主讲”是同期间通常最多一人的规则，不是强迫每个开课任何时刻都填一名教师；合法共同主讲由学校另配。

来源、覆盖、缺失、明确否定、冲突和新鲜度继续用现有质量能力，扩充教学目标适用，不复制第二套质量台账。发布来源说明记录从哪里来；独立质量声明说明特定对象、字段、时点或集合的核实状态。两者不能互相替代。

## 4. 持续任课与时间：已定规则的统一表达

### 4.1 不需要每学期重发

开课、成员来源、独立成员、任教各自有开始时间，结束时间可空。开放结束时间表示学校已确定该关系持续有效，直到正式变更或必要支持关系失效；不是每学期等待再次审批。正常换学期、升年、服务停机恢复不产生新任教行，不复制名单，也不重新发布相同开课。

学期是**查询区间或学校明确限定的安排**。只有学校把一项开课明确限定到某学期并发布截止时，才按那个截止结束；界面不能默认勾上“学期末结束”。批量导入的空结束日期同样代表无预定截止，而不是系统补上学期末。

缺少新学期记录不让开放任教失效。有正式下学期起止时，查询各关系与该区间的交集；区间内换师应分别列前后期间，不能只取开学第一天。没有正式下学期日期时，可以回答“按目前持续安排，仍由陈老师任教；下学期具体起止尚未登记”，不能编造日期、将它说成已重新确认，或假称已完整检查一个无法确定的区间。

未来已有正式交接、截止、暂停或结束时采用对应事实；对尚未发生的开放延续使用“按目前安排”。“学校刚确认了下学期仍由陈老师教”必须有那次正式发布依据，不能从开放结束时间推出来。

### 4.2 三个时间分别保留

1. **事实时间**：学校实际从什么时候开始／结束，使用含开始、不含结束的区间。例如9月10日零时换老师，9月9日是陈老师，9月10日起是李老师。
2. **登记时间**：学校何时把这条安排录入或纠正。今天补正上月交接，不伪造上月登记；通常历史查询给当前已纠正的历史，维护审计另看当时系统知道什么。
3. **访问检查时间**：现在是否有权发起查询、读取和使用结果。持续任课不续权限；7天工程职责也不等于只能查看未来7天的事实。允许的历史／未来事实范围必须由读取政策另行限定，并满足家校关系等支持期间。

正常查询不要求模型计算时间区间、升级年份或解读内部版本。模型提出“本学期”“下学期”“9月9日”等意图，领域能力根据学校正式时区／日历返回可核对的时点、区间或无法定位状态。

### 4.3 哪些情况不能沿用成另一件事

- 原班正常升年不改班名、开课或任教；新班、新课程、新群体不能因名称相似继承。
- 课程名称含“七年级”不由关键词触发自动换课。若学校正式限定了适用年级或内容，升年后超出限定应明确提示适用冲突／待维护，不把它改称八年级课程或新教材；推荐基础课程使用真实持续内容名称，年级通过正式关系说明。
- 已登记终止的开课、成员或任教不因新学期重新出现而复活。
- F4年级递进到学段末端的未知状态不等于毕业、离校、跨学段入学或退课。
- 教师任职已终止或撤销时，开放任教行不能单独证明目前仍由该人合法任教；维护时需一起核对，读取时准确区分原登记与当前支持失效，不虚构继任者。

## 5. 两种成员来源和最小例外方案

### 5.1 A：普通整班持续引用

每项开课明确引用一个F4正式行政班。在所问事实时点解析该班有效成员及其在校依据，不复制到F5形成第二份可编辑名单；也不能以开课创建时快照冒充以后持续跟随。

行政转班的生效点一到，学生从原班A来源课程离开、进入新班A来源课程；课程本身、教师和未受影响学生不用逐条改写。维护预览需说明受影响的教学关系及查询后果，不能把“不新增F5成员行”误当“没有影响”。若新班没有正式开课，回答当前没有对应安排，不继承原班课程。

来源定义版本与解析成员依据分开：同一个来源定义未改，F4归班变化仍须令查询结果失效。完整名单及成员数量只有具备对应权限和覆盖证据时才返回；家长链路只检查自己孩子是否属于所问来源。

### 5.2 B：正式独立名单

跨班组合、学校确有独立名单的选科教学等采用B。由获准人员发布每位成员和有效期间，绑定学生稳定身份及对应本校在校关系；行政转班不自动添加、删除或移动B成员。多个B群体可以同时包含同一学生，不因此冲突。

**推荐允许同一个正式群体供多项开课共用。** 界面必须显示当前及已发布未来哪些开课使用它。改群体名单时，预览所有这些开课的实际影响；只有一个课程需要不同名单时，为它使用独立的专属群体，不悄悄修改共用名单。普通整班仍用A，不为了复用统一界面创建空群体。

独立群体有一个正式组织身份，不重复人员、学生或行政班身份。若学校已有真实组织则引用；确需新群体时可以在同批维护中创建其必要组织和档案，避免让用户手工搬内部编号。

### 5.3 个别免修、加入和退出：推荐保持严格两源

“免修”可能指免考、免一次到课，也可能指正式不参加该课程。模型不能把这些都办成退课。一次免到、免考与评分不在F5；只有学校已确定正式成员变化才进入维护。

**推荐方案：** A来源课程若出现与行政班名单不同的正式成员范围，为该项开课显式切换到B。页面可按获权、覆盖已核实的行政名单生成候选，再由维护者确认最终独立名单；以后行政转班不自动同步。B内个别加入／退出直接改对应成员有效期间；跨班加入A也用同一路径。不得在A后暗加任意条件、黑名单、求并集或同步规则。

这项选择的代价必须提前说明：一人正式免修可能使该课程需要独立维护名单；此后行政转班要由学校判断是否调整这份名单。它避免了新的名单解释机制，适合本轮有限事实产品。

**备选：** 增加“行政班来源＋明确个人修读例外”事实。可以减少名单维护，但需新增例外权威、优先级、时间、共享影响及失效规则，不能当作A/B已有功能悄悄加入。建议本轮采用严格两源，是否要此备选集中见第13节。

### 5.4 来源切换和名单完整性

A→B或B→A均明确生效时间，结束旧来源区间、开始新来源区间，整批确认与原子提交。禁止同期间两源并存、求并集、查询失败回退旧源或以最后登记者取胜。

切换预览必须包括：目标、原／新来源、所问生效点的新增及退出成员、未来影响、共享开课，以及哪些任教安排拟保留或更换。当前名单不是未来名单；未来切换必须基于已发布未来事实或学校提供的正式明确名单。

只有学校确认仍是同一项持续教学任务时才保留开课身份。涉及新群体时，保留原老师也要在这次正式变更中明确说明其适用新对象，不能凭群体同名或内部编号相近自动继承。实质新课程／新班另建新开课。原B群体还被其他课使用时，切走一门课不能结束其整份名单。

来源存在与名单覆盖是两件事：B可记录部分已知成员，但必须带覆盖不足，不能把它列为全班完整名单；整批替换或由A生成完整B名单时，要求对目标时点和集合有完整依据。未录入成员不等于已正式退出。

同一孩子可以同时参加一个A来源开课和另一个B来源开课；即使两课同属数学，也应分别回答。这是两个合法教学关系；禁止双权威指的是同一开课同一期间的成员来源，并非禁止跨开课组合查询。

## 6. 正式变化、冲突和联动处置

以下“推荐”部分属于待审学校口径；已经确定的自动沿用、显式结束、历史与两源规则不再询问。

| 情况 | 设计处理 | 不允许的推断／旁路 |
|---|---|---|
| 正常换学期、升年 | 开放开课／任教延续；按F4当时年级和成员解释 | 不建年度副本、不年度确认，不自动毕业 |
| 更换老师 | 同批预览旧角色结束、新角色开始、共同任教及未来安排；按明确日期交接 | 不把新老师加进去便默认旧老师结束；不误结束其他合法角色 |
| 主讲与共同任教 | 正式角色和人数规则决定合法多值；课程内有限学科分工须显式登记 | 不能总取第一位、总判冲突或按多课猜排课冲突 |
| 持续安排暂停 | 推荐在原开课时间轴登记明确暂停段，保留原任教／成员事实并说明当前暂停 | 不等于永久结束或某节临时代课；不能称正在正常授课 |
| 暂停后恢复 | 已在同次正式安排明确恢复日的按该日恢复；未确定恢复日的开放暂停，需以后正式变更 | 不因换学期自动恢复、不自行猜暂停长度 |
| 正式结束课程 | 明确结束开课及该开课的来源、任教，列完整未来影响；共用B群体不随一门课结束 | 不删除历史，不结束其他共用课程和成员 |
| 行政转班 | A随F4事实时间变化；B不传播。预览派生影响与需正式修改的事项分列 | 不把所有教学关系按“转班”一起结束 |
| 休学 | 推荐保留独立关联，标明休学期间不能据此断言实际参加；是否暂停／退出由学校明确登记 | 不由状态自动退课、冻结所有开课或删除B成员 |
| 复学 | 推荐只沿用仍有效且明确保留的关联；需先核在校关系及正式教学安排，已结束的不复活 | 不由“在校”猜回到所有旧课；A是否归班仍以F4为准 |
| 正式转出、退学、毕业 | 推荐在确认这些事实时，一并预览并明确结束对应在校关系支持的当前B成员；尚未生效的安排明确取消、改期或纠正，不能产生结束早于开始的期间。A随在校／归班依据失效。共享课程和其他学生不受误伤 | 不从末级／年龄／预计毕业推离校；不能由一个状态字段静默代写退课决定 |
| 已有离校与开放B名单矛盾 | 当前读取不得仍把该学生列为有效当前成员；向获权维护者指出哪项支持失效，保留原记录待正式纠正 | 不先全读学生档案再裁剪、不自动改日期或删除历史；家长历史按当前访问权单独处理 |
| 班级／群体结束 | 预览所有引用开课，明确结束、换来源或另建安排；已知失效的来源不能继续证明正常开课 | 不只停群体名称留原名单继续使用；不自动继承到新班 |
| 新任职替换旧任职 | 核对原教师任教与正式交接，不能用同一人的另一个无关任职自动替代 | 读者不获得治理权，任教延续不续职工职责 |

正式离校联动的依据是学校确认的离校事实及**用户批准的学校处置规则和本次完整预览**，不是后台看到一个状态就自动退课。若学校保留离校后参加课程的特殊关系，需另定合法关系类型与访问政策，本轮不复用失效的普通在校关系放行。

### 6.1 未来取消、改期与历史补正

持续开课不能因为有一段未来换师安排，就允许“取消未来安排”把整个开课根删除。应精确选择目标未来片段及这次安排造成的关联结束：

- 取消尚未生效交接时，仅在有因果记录、旧任教未被后来独立修改的条件下恢复被这次安排截断的期间；原来独立截止的日期不得延长。
- 改期要一起重算旧老师、新老师和中间区间，不能只改新老师开始日留下空档或重叠。
- 今天补正上月更换，保留上月实际日期与今天登记日期；有界纠正，不覆盖区间外后来合法安排。
- 若未来新成员、共同任教等受影响，全部列入同一预览；无法确定时拒绝原候选并重新核对，不静默吞掉。
- 当前F4切片和结束因果能力可复用，但其取消约束尚不能直接支持持续教学对象的任意未来片段，须有明确增量及回归证明。

### 6.2 一次确认必须对应一个完整原子变更

预检计算全部影响，包括只改变派生查询的影响。准备之后新增了共享开课、成员、任教、未来安排、质量声明或权限，提交时必须发现；不能只锁住当时看见的几行就称影响集合未变。

沿唯一Writer采用当前学校／相关集合版本、完整条件依赖及事务内重验，必要时合适的锁和唯一约束共同防止并发遗漏。跨F3、F4、F5的规范变更仍在同一正式批次提交，不建立第二执行器。需修改的对象没有完整写权，或影响无法完整核对时，整批不执行；维护人员不能用家长报错或模型说明补出缺失权限。

F4转班只改变A的派生成员时，使用限定于本次学生、班级和相关开课的影响读取，不能因此要求维护者取得全部F5名册或写权。若确需修改B成员、来源或任教，则另核这些明确对象的写权。职责建议包含这一最小联动用途；未具备时拒绝该候选并指出缺少的用途，不扩大读取。

重复确认查同一回执，不重复改事实。提交结果未知先查原回执，重启、新登录和重新打开页面不生成新批次。停止模型回答不撤销已正式执行的修改。

## 7. 查询与维护权限矩阵

以下推荐沿现有用途、对象、字段分离，不建立新权限平台。家长学生／相关教师／领导三条边界已由用户确定；具体合成职责名单及期限在第13节一次审阅。

| 身份／用途 | 对象与字段 | 历史／未来 | 不自动获得 |
|---|---|---|---|
| 当前核实监护人：孩子教学 | 当前选中、获权孩子；其正式开课、课程与学科、相关教师姓名／任教角色、获准官方渠道 | 当前仍有效家校关系须覆盖所问期间；未来只能返回已发布安排或有依据的持续延续 | 其他学生名单、姓名、职务；教师私号、人事资料、维护权 |
| 当前家长：学校领导目录 | 当前家校关系绑定本校的正式领导姓名、职务、真实学校／校区职责范围、获准官方渠道 | 推荐默认当前；历史／未来须另有明确时间读取许可，不因教学未来许可顺带开放全部领导人事历史 | 任命依据原文、内部审批号、私人联系、治理身份；不要求领导直接教孩子 |
| 学校认可照护人 | 继续原已批准用途和最小字段；不把监护人新增教学字段自动给照护关系 | 沿F3已有期间和限制 | 监护人专有字段和全部教学历史；需扩展另明确用途 |
| 普通职工：教学结构读取 | 明确授予的课程、学科、班级／群体安排、任教与组织适用范围 | 推荐可查这些当前获授对象／字段的已登记历史和已发布未来，不设学期末或职责截止日为事实日期上限 | 全校学生明细、全部私人联系及写权 |
| 教师：本人任教查询 | 经当前身份定位本人正式任职；授予“本人任教查询”用途后查自己的开课与对象 | 推荐可查当前用途涵盖的本人已登记历史和已发布未来；不由过去任教自动取得当时学生档案 | 任教关系本身不是权限授予；不是自动全班资料维护者 |
| 教师：教学学生工作读取 | 另获明确教学对象／字段用途后，读取相关当前成员姓名、必要学号和成员期间 | 只在当前授权及允许事实范围内 | 家庭信息、其他课程名单、同组织全部学生 |
| 教研／备课成员 | 获授组织读取用途后查本人组织及其正式适用范围；成员名单另按用途核验 | 组织关系与当前职责分别检查 | 不自动继承学科、年级或组织后代的数据权限 |
| 教学维护者 | 指定事实族及明确学校／课程／群体／对象集合的维护与必要影响读取 | 原时间轴、未来候选及有依据纠正；读写分别核验 | 自授、他人回执、范围外共享名单或F2/F3全部维护权 |
| 职责授撤操作者 | 既有独立治理路径，绑定本次固定职责与期间 | 短执行窗口；结束后关闭 | 普通事实维护、验收家长治理权、自动续期 |

“我的任课”使用当前可信人员／任职身份，不接受模型传入另一个教师身份冒充本人。一个用户兼教师和家长时不合并权限；切身份、切孩子后旧结果及待确认候选按原机制失效、重验。领导查询不依赖所选孩子任教，但学校锚定仍来自当前有效身份，不能由口语改到另一学校。

职工事实时间的上述推荐由F5领域权限策略与读取范围合同落实：先确定现在获准的对象／字段，再在SQL前确定所问事实期间与来源条件。当前F4范围合同没有独立历史／未来窗口字段，不能声称已实现这种新增政策；本轮建议允许当前对象范围内全部已登记历史和已发布未来，不另发“跨学期读取权”。需要更窄历史窗口是备选学校政策，不能靠7天工程职责截止日代替。登记认知时间不超过当前时刻；未来延续仍受支持关系及正式变更限制。

### 7.1 学校领导目录的独立补接

已证实缺口：家长装配直接进入只含孩子资料／教育工具的入口；现F2目录规则和HTTP（网络接口）只接受职工。不能直接把职工网关给家长，也不能仅靠隐藏前端字段解决。

推荐由**F2学校目录所有者**增加有限家长领导读取合同：复用现有正式任职的语义角色、人员和组织，按学校正式领导职务类型定位，不根据职位名称关键词或组织名猜“领导”；是否任教孩子不参与判断。正副、代理、多校区等按真实任职表达，学校与校区负责人的范围不能混称。

在数据库读取前就限定同校、当前正式任职及家长允许字段。现职工任职投影包含任命来源、审批引用等内部字段，家长投影不得取出后再删除。姓名／正式职务无需另设“个人同意公开姓名”的新门；官方渠道仍须学校批准面向家长提供。

给家长装配教学工具与此目录能力；复用同一身份、当前授权、时间、依赖和结果释放控制。正式角色语义映射由学校配置，不在内核写“校长”关键词。学校领导资料维护仍归原人员／任职／组织Writer，不在教学群体造一份领导关系。

领导身份／岗位已确定但渠道未录入时，照常回答是谁并单列渠道缺项；不能因为没有电话号码而拒绝姓名。组织办公室邮箱必须标出所属渠道，不能包装成领导或老师私人邮箱，也不能无依据承诺转接或受理。

## 8. 录入、批量维护、纠错的完整操作

### 8.1 单项及成套录入

1. 选已有学科和课程，或在授权范围内登记正式新对象；名称有歧义时给可读候选，保留来源中的稳定引用，不要求用户手工输入内部编号。
2. 登记正式开课，选行政班A或独立群体B，明确开始时间；默认无预定截止，只有实际有截止才填写。选学期可帮助填写明确日期，不能自动变成必填截止。
3. B选择现有共享群体或创建专属群体，维护明确名单及期间；显示所有引用课程。相互依赖的课程、群体、名单和任教可在一个受控批次提交，不留下引用不存在对象的半套关系；已确定开课但名单覆盖不足、教师未录入或正式空缺可以如实发布，不能冒充完整安排。
4. 选择真实教师及任职、主讲／共同任教角色与必要范围。默认沿用，不要求“下学期重新确认”。
5. 预检显示新增、更新、结束、无变化、错误、受影响但不写入的对象，并区分现在和未来生效；重要影响全部可读。
6. 维护者明确确认后执行一次；显示真实成功／失败／未知和原回执；再查当前或指定未来值。失败不假称“已提交给学校处理”就是事实已修改。

### 8.2 批量导入与完整替换

推荐新增有限教学导入模板，支持课程、课程学科、开课、来源、独立成员、任教和组织适用，复用原规范批次及来源映射。旧模板保持原解释；新模板显式版本，未知列／冲突引用报错，不静默忽略。超长正式说明不静默截断；普通展示可简短但详情能读取完整正文。

- **增量导入是默认。** 文件没有出现的对象保持原状；空单元格须区分“本次不修改”“明确清空允许字段”“无预定截止”，不能一律覆盖空值。
- **完整替换必须主动选择。** 明确替换哪个群体或开课、哪个期间及集合边界；有获权完整基线才计算遗漏退出项。未来名单和历史期间不能被当前文件覆盖。
- 相同稳定引用／内容无变化就列无变化，不人为更新来源和版本；重名但没有可靠来源映射先消歧，不自动合并或制造重复根。
- 错误、缺权限、同期间两源、重复成员或任教、跨校引用、未来冲突均在确认前列出，整批不成功一半。
- 当前教育批次最多300项；F5应在实现后计算**含联动展开**的实际批次容量。超限提前拒绝并说明，不暗中拆成多笔。多个互不依赖的教学任务可以由维护者明确拆开；一项必须原子的来源切换／重组不能拆开伪装通过。

### 8.3 家长报错与正式处理证明

家长在自己孩子的查询结果选择“课程不对”“老师不对”“安排时间不对”“官方渠道有误”等有限字段，后端生成与当前孩子、对象、字段和读取结果绑定的签名目标；不允许前端自由输入另一个学生或教师目标。

新教学目标必须接入：读取投影 → 报错可选项 → 后端有限字段合同 → 数据库目标／字段白名单及差异证明函数 → 唯一Writer真实变更 → 原回执精确差异证明 → 处理结果 → 家长重新查询。现有报错表没有事实类型／字段枚举CHECK（表级约束），限制主要在受控SQL与Python合同；要一起核对实际表约束兼容。F4已发生过枚举及前端只认识旧类型的缺口，F5必须一次检查所有已启用消费者，不能只多一个页面按钮。

家长可以报告课程关联问题，但不能凭报错授予自己名单读取权。维护者以自己的当前职责核实；要把报错标记为“已修正”，须证明原回执中的正确对象和字段确实被正式修改。一个任教关系是多人共用时，预览和处理证明仍指向正式共同对象，不复制一个“仅该家长可见”的修正答案。

没有修改事实的解释／无变化不能冒称已修正；允许记录“已核实，原资料无误”及可读说明，但应保留其与正式变更的区别。该状态如现有合同不具备，作为最小报错状态增量一并测试。领导目录的事实报错沿F2目标所有者接入，不伪造成孩子教学报错；权限不足给获准渠道，不能自动创建流程。

## 9. 查询合同、证据分层与性能设计

### 9.1 有限组合查询，不逐句制造工具

建议按三类领域需求提供能力：孩子教学关系／本人及范围内任教组织查询／学校领导目录。具体数量由现有工具装配决定，不规定每问只能调用一次。正式维护继续用已有准备、确认、回执能力。

“孩子数学老师是谁”的领域链路先由可信身份确定孩子，再限范围查该孩子的A归班与B成员、有效开课、课程学科、任教及姓名。只在请求联系时加入获准官方渠道；不读全校目录、整班名册、全部教师档案或所有质量历史。不逐门课重复读取相同身份和在校依据。

有两个合法数学相关开课，就一次返回两组有明确归属的课程／老师。只有同名或目标真的不明确才返回获准候选；数据缺项、范围内无记录、正式空缺或能力尚未接入不反复追问用户工具无法使用的信息。

领域结果保留以下区别，模型用大白话表达，不直接把机器状态名交给老师：

| 事实状态 | 正确结论与后续 |
|---|---|
| 对象未找准／确有歧义 | 说明尚未确定哪个班、课程或群体；只给获准候选，不替换成默认对象 |
| 能力不支持 | 说明当前不能查询或办理该类事项，不冒称资料未录入 |
| 范围内无当前记录 | 只说明核查范围和时点内没有匹配有效记录；不升级为从未开课或没有老师 |
| 已明确未录入 | 有针对该对象／字段／期间的正式缺失声明才这么说 |
| 正式空缺／明确不存在 | 按各事实类型的正式否定范围说明；“岗位空缺”不是老师个人不存在 |
| 合法多人／多课程 | 完整对应课程、角色、时间；一条记录不代表唯一，多条不自动冲突 |
| 资料冲突 | 指出影响结论的矛盾，不能选一条伪装确定；保留获准纠错渠道 |
| 无权限 | 不透露未获准候选、姓名或记录存在性；不说成学校没有资料 |
| 覆盖不足／过期／来源不可用 | 分别说明本次结论的范围、时效或依赖故障；已有有效结果能否部分提供由领域合同判断 |

每个结果还带当前／历史／未来事实时间、登记来源和必要依赖。某集合未声明完整覆盖不自动否定已查到的单条关系；单条有发布依据也不证明整个集合完整。

对于“本学期我教哪些班”或“该组覆盖哪些年级”，只查本人任教或获权组织的关系，关联名称和时间由领域受控完成。模型不为每个内部编号再查全表。教研范围默认推荐明确固定年级或明确学年年级；是否随届别推进是另一个正式口径，不能从组名推断。

家长泛问“孩子有哪些相关老师”时，可在获准范围内合并F4班主任及F5任课关系，按角色和课程说明同一个人的不同职责，避免重复数成人数；教研组成员不是自动相关教师，学校领导目录也不混入孩子的任课清单。

### 9.2 依赖完整，连接短占用

一次同步读取内可复用相同身份／范围依据，批量取得必要关联；结果再次使用和模型等待后必须当前重验。不能整轮只验一次、跨身份缓存或先全读后裁剪。

结果依赖至少包括：当前家校或任职身份、当前许可；来源定义；A的归班条件集合或B成员集合；在校关系；课程与学科；开课、任教、组织与人员名称；所请求渠道；质量／来源／覆盖；开始、结束、暂停和学校日历边界。空结果也记录条件及集合依赖，新增匹配项后须失效，不能只记已返回对象版本。

推荐先沿现有版本／有界指纹证明，避免新建通用缓存。全校版本可作为保守变更信号，但变化后只重核本查询的授权目标与依赖，不逐族全量遍历。集合新增与时间边界不能由单个对象版本替代。

数据库连接仅在真正执行受控读取／事务时借用，及时归还；模型推理、等待用户确认和阅读历史时不占连接。结果使用时另取短连接复验，不通过长事务固定旧权限快照。多用户分别记录借出／归还、新建连接、等待和池上限，不能无限新建连接，也不因排队跳过安全检查。

检查和实际使用沿已有同步受信任边界绑定；跨模型等待、身份变化或新一轮使用必须重新核对。数据库事务内的同次观察有明确时点，检查后发生的新变更会使后续使用失效重读；不能宣称已经显示给用户的文字始终反映此后每次变更，也不靠持续持有数据库连接来制造这种保证。正式确认仍在Writer事务内重验当前授权和全部影响。

## 10. 数据库、合同兼容及回退建议

### 10.1 推荐增量方向与备选

**推荐：** 复用F4教育根／双时间版本／同校引用及规范Writer，建立独立教学类型合同和F5职责集合；为成员来源、成员及任教补足有数据库保障的业务约束。应用装配按事实所有者分区，F2目录、F3学生、F4班级和F5教学各守原语义，不按业务模块启停增减Writer具体分支。

**备选：** 针对来源／成员／任教使用更专用的关系表，仍共用唯一Writer和原回执。优点是强约束和索引更直接；代价是更多追加结构和迁移适配。只有实际证明现有三表无法清楚表达必要约束或有效查询时才采用局部专表，不全面重写，也不让用户选择表数量。

两种方案都必须满足以下约束，不能以JSON（结构化字段）里写了类型名就声称完成：

- 学校、稳定来源键、对象类型唯一；所有外键和引用限定同校与合法目标类型，删除受引用对象受限。
- 每个稳定事实当前认定的有效区间不重叠；区间结束大于开始，登记历史不覆盖。
- **跨不同来源键**的同一业务关系也要受约束：同开课、同成员范围、同时间段只能一个A或B；同群体／学生重复成员不得重叠，不能换一个在校关系引用绕过；重复相同任教关系不能冒充共同任教。
- 合法多人按已发布角色／人数规则验证；共同角色、跨课程、同学科多课不得错误地被单人唯一约束拒绝。可在数据库使用规范业务键与区间互斥，跨对象的规则由事务内最终校验保障；不能只有客户端扫描。
- 当前在校关系、正式任职、来源对象及共享引用的有效性在预检和提交时核实；存量矛盾可保留审计，但新写不能绕过有效性，读取不能拿无支持记录当当前有效成员。
- 行级安全、窄读取函数与字段白名单、只读和写入角色边界保留；新增投影不给产品角色任意表查询权。
- F4原17类范围显式保留。当前F4策略直接别名整个教育类型集合；须先拆清F4／F5批准集合及操作命名，避免新类型自动进入旧F4职责或旧查询。
- 规范输入版本、旧回执解码与原导入语义兼容。新类型／操作有明确准入；旧合法请求继续工作，未知类型拒绝，不能宽松放行。

### 10.3 相容更新与回退

实施前清点真实库是否有教学相关旧记录、导入来源或外部消费者；本轮没有据空代码目录声称正式库永远无旧数据。发现旧数据时先说明权威与映射，不能无依据自动并入新名单。推荐不迁移既有学校事实身份、不重放旧动作；新增教学通过正式发布。

先在独立受控测试库验证追加结构、旧F3/F4请求和原回执，再准备匹配Product（产品应用）、Writer与前端制品；原实例只追加迁移，不改历史迁移。保护原数据、账本、权限、审计、挂载和故障备份，杭州不在范围。

回退优先关闭未就绪F5能力或换回已核结构兼容制品。现Reader严格核对数据库版本；即便尚无F5记录，追加迁移也可能使F4旧镜像拒绝启动，不只是能否理解新枚举的问题。新版本必须在Product／Reader／Writer结构与配置白名单中匹配，并保留Writer最终授权守卫和家长身份验证的强制条件；主制品和兼容回退制品同批验证，证明F3/F4旧入口仍可用后才允许更新。

新写入和费用不倒退，已撤权和关闭记录不复活；不通过回滚数据库抹去正式动作。所有未知执行先查原回执。

## 11. 固定验收设计

### 11.1 判定与证据口径

准确性、任务完整、权限、表达、速度分别判定。查询、正确澄清、拒绝、不支持、故障分别记录；权限拒绝不是有效查询速度。旧F4测试仅在代码、合同及环境适用时复用，教学接入影响的共享路径必须回归，但不重开F4整体验收。

正式实施开始前固定拟用样本、身份、范围、时点、题单、期望结果及起始代码基线；每批验收开始前再冻结实际发布资料和受测代码／制品，不按速度事后重新分类。早期贯通证据记录对应版本，后续相关代码或资料变化按影响复验，不能自动当作最终制品证明。机械／真实数据库负责控制与事实，模型及浏览器负责真正使用与表达，不能互相替代。模型不自评通过；人工能核对最小结果与正式来源，但不持久保存完整提示、回答或思考正文。

### 11.2 固定机械与真实数据库场景

以下每项都要求明确正例、反例和真实数据库中受影响的依据；“复用”须登记来自哪个有效测试及为何仍适用。

### 11.3 拟合成资料及固定真实模型／浏览器题单

建议采用**独立标识的合成验收对象**：两校区、三行政班（含跨校区同名）、至少八名学生、两孩监护人、教师兼家长、有限维护者；四学科、五课程、六项开课；两个B群体，其中一个供两课共用；主讲／共同任教／未来交接教师、正式学校领导和校区负责人、教研／备课组织、获准组织邮箱。另有缺渠道、覆盖未知、明确空缺、无当前安排及受限制字段样本。

这是待批准的最小覆盖建议，不是当前正式库已有数量。可复用可靠F4对象与关系；需要新组合就在隔离样本中通过正式路径发布，不能改变F4已验值凑答案。学校规则、老师和领导姓名都以实际发布为准，示例“陈／李”等不写入提示当固定答案。

### 11.4 推荐速度标准与有限停止条件

| 类别 | F5推荐标准（待审） | 测量终点 |
