# 第三阶段公共能力设计







## 1. 目标与边界

第三阶段为后续业务提供统一公共能力：教职工通过钉钉进入系统，后端依据可配置的角色、操作和数据范围决定是否允许访问；关键操作与权限变更可追溯；手机拍摄的照片作为私有业务附件保存。

本阶段不创建校园地点、统一反馈、宿舍、违纪、库存、RAG 或聊天业务模块；也不提前实现万能权限编辑器、通用工作流、视频上传、人脸自动打码或钉钉故障下的独立密码登录。

## 2. 钉钉身份与管理员登录

### 2.1 统一登录方式

所有用户，包括系统管理员，均从钉钉自建应用进入。后端验证钉钉返回的企业内人员唯一身份后，映射到本系统用户；系统角色由本系统维护，不能直接以钉钉部门或钉钉企业管理员身份替代。

```text
用户打开钉钉自建应用
→ 钉钉完成企业身份确认
→ 后端验证身份并查找本系统用户
→ 后端读取用户角色和数据范围
→ 返回普通入口或管理员维护入口
```

### 2.2 初始管理员

学校在部署时指定两名初始系统管理员，并以其钉钉企业身份绑定系统管理员角色。两人均可通过钉钉进入维护页面；不存在默认密码或公开的本地超级管理员。

钉钉企业管理员负责钉钉后台和自建应用配置；系统管理员负责本系统的人员、角色、地点和业务基础数据。两种身份可以由同一人承担，但权限不自动互相授予。

## 3. 集中、可配置的授权

### 3.1 判断原则

权限只在后端集中判断，前端仅按后端结果展示界面。每一次访问按三个维度判断：

```text
用户角色 + 请求操作 + 数据范围
```

例如，“总务责任处理人”拥有 `处理反馈` 操作，但只能处理其负责地点或部门范围内的记录；不是因为页面上显示了按钮就能处理全校记录。

业务模块不得散落 `if 老师`、`if 领导` 等角色判断。模块只声明自己需要的操作与数据范围，授权公共能力统一作出允许或拒绝决定。

### 3.2 初始角色和默认范围

| 角色 | 初始能力 | 初始范围 |
|---|---|---|
| 普通教职工 | 查看公开资料、提交本人可提交的业务、查看本人记录 | 本人及公开数据 |
| 责任处理人 | 受理、处理中、完成其职责内的业务 | 负责地点或本部门 |
| 值周/检查人员 | 录入检查、上报需要核实的线索 | 指定检查范围 |
| 学校领导 | 查看授权汇总、复核需要确认的事项 | 指定部门或全校 |
| 系统管理员 | 维护人员、角色、负责范围和基础配置 | 系统配置；不自动取得所有业务处理权 |

班主任、年级组长、政教主任、后勤主任等属于学校常用的预置示例角色，不是写死在代码中的固定枚举。实施时由管理员为这些角色配置实际操作和数据范围；尚未实现的业务模块不会因预置角色而自动产生权限。

“全体可查看”只适用于公开制度、校园地点和明确公开的处理状态；原始照片、上报人身份、内部备注、请假健康、学生违纪、扣分和人员资料默认不公开。

### 3.3 后台可调整规则

后台配置支持调整已有人员的角色、责任地点或部门范围，以及已有操作的角色授权和数据范围。常见调整无需改业务代码或重新发布。

新增全新的业务操作、敏感数据类型或确认流程时，仍需先完成该业务模块设计；配置不能绕过业务规则、状态机或学校制度。

权限规则变更对新请求立即生效；每次变更必须记录审计，且能够按审计记录恢复到上一个已知配置。

当前实现不缓存权限判断结果；每次请求重新读取 PostgreSQL 中的用户状态、角色权限和责任范围。未来若引入缓存，必须先具备跨进程版本校验或失效协议，禁止使用无法及时失效的进程内权限缓存。

## 4. 审计留痕

审计用于回答“谁在什么时候对哪条记录做了什么”，不等于监控所有聊天内容。至少记录以下关键事件：

- 登录身份绑定、初始管理员绑定和角色、范围、权限规则变更；
- 后续业务的创建、受理、完成、确认、退回、删除或导出；
- 文件上传、查看原图、下载原图和匿名身份追溯。

每条审计记录保存操作人内部身份、操作时间、操作类型、目标资源、变更前后摘要、结果、请求标识和必要原因。审计记录只追加、不允许普通系统管理员删除或篡改。

## 5. 匿名与实名上报身份显示规则

### 5.1 独立规则

匿名或实名不是固定页面逻辑，而是独立的“上报身份显示规则”。每个业务类型可以配置：是否允许实名、是否允许匿名、默认选项、匿名时的可见角色、匿名身份追溯角色，以及是否允许匿名追问。

每条上报记录必须保存真实上报人、提交时选择的身份展示方式和当时生效的规则版本。真实身份不会因选择匿名而从系统或审计中丢失。

### 5.2 可见性与历史保护

匿名上报时，普通查看者和责任处理人只看到“匿名教职工”，不看到姓名、部门或联系方式。仅配置中的指定追溯角色能在处理争议、恶意上报或学校规定的情形下查看真实身份；每次追溯都写入审计。

规则修改只影响之后新提交的记录。历史记录继续遵循提交时保存的身份展示方式和规则版本，不能因后来规则调整而暴露上报人。

学生违纪、扣分、处分、请假健康等高影响事项，匿名信息只能作为待核实线索，不能直接形成正式处理、确认或扣分结果。

## 6. 手机照片私有附件

### 6.1 上传规则

教师通过钉钉拍照或从相册选择图片。第一版支持 JPG/JPEG、PNG、HEIC；每次最多 6 张、单张最多 10MB；暂不支持视频、压缩包、PDF 或其他文件类型。

服务端必须校验真实文件内容、MIME 类型、大小和图片可解析性，不能只根据扩展名判断。手机照片生成可在线预览的缩略图；HEIC 同时生成可预览图片。常规业务图片在保存和预览时去除 GPS、手机型号等 EXIF 隐私信息，不依赖照片定位判断业务地点。

### 6.2 私有存储与高峰处理

原图与预览图保存在私有 MinIO `uploads` 桶，数据库仅保存文件元数据、所属业务记录、上传人、哈希、大小、类型和访问关系。对象名称使用不可预测标识，不使用公开静态 URL。

后端校验用户和业务记录的上传权限后，先在 PostgreSQL 创建业务记录和 `pending_upload`
附件记录，再签发绑定唯一临时对象或受版本控制对象的短时上传凭证。客户端直传私有 MinIO
后，确认接口检查对象归属、大小、真实类型和强校验和，并采用以下一种经过能力核验的固化方式：

1. 保存本次已校验对象的 `version_id`，后续始终精确读取该版本；
2. 按源版本或条件校验把临时对象复制到客户端不可写的唯一最终键，并再次验证最终对象。

只有固化和最终验证成功后，附件才改为 `available` 并完成业务绑定。不能仅保存哈希却继续
允许原上传凭证覆盖正式可访问对象；旧凭证无法提前撤销时，后续写入只能落到不再引用的临时键。

对象已上传但确认失败时允许使用同一幂等键重试。过期清理任务只处理超过有效期且仍为 `pending_upload` 的附件；对象不存在按幂等成功处理，删除失败进入有限重试和死信。附件状态属于每个附件或上传会话，不在业务表保存单个 `file_uploaded` 布尔字段。

### 6.3 查看与下载

默认可在线查看照片的是上报人、该记录的责任处理人和授权领导。即使某条业务的处理状态可被全体查看，原始照片也默认不向全体公开。

原图下载权限独立于在线查看权限，默认不开放。纪律、健康、人身安全等高敏感照片通过应用
或认证文件网关逐请求重新鉴权和输出；文件较大不能降低敏感等级。只有普通或低敏感照片才可
在后端重新鉴权后签发短时、精确对象与版本、只读的预签名 URL；它是短期 bearer 凭据，
不能宣称绑定实际点击者。需要单次、可撤销或严格会话绑定时使用原子消费的应用访问票据，
不能把该票据等同于对象存储预签名 URL。匿名上报的照片同样遵循匿名规则，界面提醒上传人
避免拍摄无关学生正脸、工牌和电话号码。

照片数量、单张大小、业务类型是否允许上传、保留期限和查看范围属于后台配置；私有存储、真实内容校验和短时受控访问属于不可关闭的安全底线。

## 7. 测试环境与正式接入隔离

### 7.1 三套环境

系统分为本地开发、测试/试用和正式生产三套环境。三者的数据库、Redis、MinIO 桶、钉钉应用凭证、回调地址和日志必须彼此隔离，测试环境不得读取或写入正式环境数据。

| 环境 | 使用人员 | 身份来源与数据 |
|---|---|---|
| 本地开发 | 开发者 | 模拟钉钉身份和自动化测试数据，不依赖真实钉钉企业 |
| 测试/试用 | 受邀测试人员 | 用户创建的测试钉钉企业、测试自建应用、测试地点和测试照片 |
| 正式生产 | 学校授权用户 | 学校正式钉钉企业、正式自建应用和学校正式业务数据 |

### 7.2 测试企业模拟学校

测试钉钉企业作为模拟学校使用。测试管理员在其中创建测试版自建应用，邀请教师、后勤、领导等测试人员，并为他们配置测试角色、测试地点和测试范围。

测试阶段可以验证钉钉免登录、角色调整、匿名上报、手机照片上传、权限拒绝和页面易用性，但不录入真实学生纪律、请假健康、人员隐私或正式业务照片。

测试企业的钉钉人员身份与学校正式企业不同，因此正式上线时不得复制测试人员身份绑定。可迁移的内容是经确认的角色规则、权限配置、地点模板、验收用例和测试结论；正式企业中的初始管理员、责任人和角色成员必须重新绑定。

### 7.3 稳定性试用与逐步上线

功能与易用性由受邀测试人员在测试企业完成；接口稳定性使用模拟身份和测试数据进行自动化并发验证，不依赖真实人员重复操作。

测试通过后，学校正式钉钉企业先只授权 3 至 5 名试点人员使用。试点确认登录、权限、照片访问和审计均符合预期后，再按学校决定逐步开放给更多教职工，而不是一次性开放给全校。

## 8. 预期实现边界

第三阶段实施时，才按实际需要创建以下区域；第二阶段已存在的 `apps/api/app/` 继续复用：

```text
apps/api/app/platform/identity/
apps/api/app/platform/authorization/
apps/api/app/platform/audit/
apps/api/app/platform/files/
apps/api/app/integrations/dingtalk/
```

实施计划确认前不创建上述目录。后续实施计划必须逐项说明数据迁移、权限配置初始化、钉钉回调验证、私有 MinIO 访问、错误提示、审计写入和测试方式。

## 9. 验收示例

1. 已绑定的普通教师从钉钉进入，只能访问公开内容和本人记录；未绑定身份不能获得系统访问。
2. 系统管理员把某教师加入责任处理人并指定地点后，该教师刷新页面即可获得该地点的处理权限；无需退出钉钉、重新登录、重启服务或发布配置，且变更有完整审计记录。
3. 普通教师无法仅因前端按钮或接口地址而处理非负责范围内的记录，后端返回安全中文拒绝提示。
4. 匿名上报的责任处理人看不到上报人身份；指定追溯角色查看身份后，系统记录该次追溯。
5. 修改匿名规则后，先前匿名记录仍保持原有匿名保护。
6. 手机 JPG、PNG、HEIC 照片可上传；超出数量、大小或格式时返回清晰中文提示；对象存储中不存在公开永久访问地址。
7. 有查看权限者能在线预览照片；无下载权限者不能取得原图。客户端先向后端申请短时上传
   凭证，再直传私有 MinIO；上传完成后，后端按对象版本或不可写最终键固化并验证后绑定业务
   记录，旧上传凭证不能覆盖已确认内容。上传流不经过后端；高敏感查看/下载可以按逐请求鉴权
   规则经过受控文件网关。
8. 高敏感大图不会因体积改用普通预签名下载；普通短期 URL 按 bearer 风险处理，单次票据
   并发兑换只允许批准次数内的请求成功。
