# 第二阶段最小应用骨架设计





## 1. 目标与边界

本阶段只证明项目能以可重复的方式运行“浏览器 → 前端 → 后端 → PostgreSQL”的最短链路，为后续身份、权限、校园地点和统一反馈提供可靠起点。

本阶段交付：

- FastAPI 应用、受控环境配置和 PostgreSQL 连通性检查；
- `GET /api/v1/health` 健康接口；
- Alembic 迁移配置与可执行的初始迁移基线；
- Vue 3 + Vite 前端健康页面，以及到后端的 `/api` 开发代理；
- 后端单元测试、后端真实数据库验证、前端构建验证。

本阶段明确不交付：登录、角色权限、审计、文件上传、业务领域模块、聊天、RAG、Redis 业务使用、MinIO 业务使用、DeepSeek、语音、通用平台目录或任何业务数据表。

## 2. 方案选择

采用“最小全栈骨架”方案：后端与前端在同一阶段创建，使用当前已验证的 PostgreSQL 容器。后端采用 Python `venv + pip`，前端采用 `npm`；暂不增加 Poetry、uv、pnpm 等额外工具。

不采用“后端先行”方案，因为它无法满足本阶段“前端经 `/api` 代理访问后端”的验收要求；不采用预建所有模块方案，因为它会产生协议禁止的未来空壳。

## 3. 目录与组件

本阶段只首次启用以下目录和必要文件：

```text
apps/
├─ api/
│  ├─ pyproject.toml
│  ├─ alembic.ini
│  ├─ alembic/
│  ├─ app/
│  │  ├─ main.py
│  │  ├─ core/               # 当前只放 Settings 与安全错误响应
│  │  └─ db/                 # 当前只放 SQLAlchemy Engine、会话和迁移元数据
│  └─ tests/                 # 健康接口与配置行为测试
└─ web/
   ├─ package.json
   ├─ vite.config.ts
   └─ src/
      └─ app/                # 当前只放健康页面入口
```

不创建 `platform/`、`domains/`、`integrations/`、前端 `features/`、`shared/` 或顶级测试目录；这些目录没有已确认的当前用途。

## 4. 后端设计

### 4.1 配置

后端从项目根目录 `.env` 读取 `APP_ENV`、`POSTGRES_HOST`、`POSTGRES_PORT`、`POSTGRES_DB`、`POSTGRES_USER` 与 `POSTGRES_PASSWORD`。数据库 URL 在服务端由这些字段组合，不在前端暴露，也不把真实密码写入仓库。

本地后端连接 `127.0.0.1:${POSTGRES_PORT}`；容器内服务名称只在未来后端容器化时采用，当前不提前加入该分支配置。

### 4.2 数据库与迁移

SQLAlchemy 仅提供 Engine、会话工厂和一个用于健康检查的只读 `SELECT 1` 探测函数。每次健康请求独立获取并释放连接；不得把连接或会话保存在全局请求状态中。

Alembic 配置读取同一套 Settings。初始迁移版本只建立 Alembic 的迁移历史基线，不创建任何虚假的业务表或未来字段。该版本有当前用途：让空数据库能稳定升级到项目已知的架构版本；下一阶段出现真实身份或权限实体后，才创建第一个非空业务迁移。

### 4.3 健康接口

接口固定为 `GET /api/v1/health`，返回：

```json
{
  "status": "ok",
  "database": "ok"
}
```

数据库探测失败时，接口返回 HTTP 503 和安全中文提示“数据库暂时不可用，请稍后重试。”；服务端记录异常，不向浏览器返回连接串、密码、堆栈或内部路径。

## 5. 前端设计

前端采用 Vue 3、TypeScript 与 Vite，不引入 UI 组件库。首页只显示“校园综合智能体正在连接服务”，加载时请求 `/api/v1/health`：成功时显示服务与数据库可用；失败时显示中文的可重试提示和“重新检查”按钮。

Vite 开发服务器监听 `5173`，把 `/api` 代理到 `http://127.0.0.1:8000`。浏览器只与 Vite 同源通信，因此开发阶段不需要额外 CORS 配置；后端也不放宽任意来源访问。

## 6. 测试与验收

后端遵循测试先行：先为健康接口的成功与数据库故障分别编写测试，确认测试因实现缺失而失败，再写最小代码。配置测试验证缺少必填数据库配置时启动失败且不泄露密钥。

本阶段完成必须同时满足：

1. `alembic upgrade head` 能对空 PostgreSQL 成功执行初始迁移基线；
2. 后端测试、Ruff、Pyright 全部通过；
3. 启动 Uvicorn 后，请求 `/api/v1/health` 返回 HTTP 200 与约定 JSON；
4. 前端构建通过；启动 Vite 后，浏览器页面可经 `/api` 显示真实健康结果；
5. `.env` 仍被 Git 忽略，新增文件、目录均登记到《学校综合智能体平台文件说明》。

## 7. 风险与控制

| 风险 | 控制方式 |
|---|---|
| Windows 本机 Python、Node 或 npm 不可用 | 先只读检查版本；缺失时停止并说明需要安装的工具，不替用户静默安装。 |
| PostgreSQL 未启动或端口冲突 | 健康接口安全返回 503；实施时先检查 Compose 状态和连接。 |
| 为了迁移测试而提前创建业务表 | 初始迁移只建立 Alembic 架构版本基线；业务表必须等对应模块设计确认。 |
| 前端与后端接口不一致 | 前端只请求固定健康接口；后端 OpenAPI 自动生成并作为后续客户端契约来源。 |

## 8. 后续衔接

第二阶段完成后，下一阶段根据已确认路线先实现身份、授权、审计和文件四项公共能力。它们通过新的模块设计、迁移、测试与文件说明登记逐步加入；本阶段骨架不为它们预留目录、字段或接口。
