# 三个阶段与设计阅读顺序

本包公开三个长期产品阶段的设计，不宣称三个阶段都已建成。

| 长期阶段 | 设计方向 | 当前交付边界 |
|---|---|---|
| 第一阶段：校园业务基础与小静 | 学校事实权威、自然语言入口、身份授权、独立校园业务模块 | F1—F8学校事实及小静有实现和原项目验收；普通业务模块与真实学校上线不是全部完成 |
| 第二阶段：设备接入 | 经独立设备模块和受控设备API适配现有设备 | 设计方向，未交付设备控制系统；不能让模型直控设备或把当前数据库接口称为设备接入 |
| 第三阶段：教学能力 | 经教学业务模块、语音转文字适配和模块呈现端提供教学服务 | 设计方向，未交付完整教学应用；F5课程/任课“事实查询”不等于课表求解、课堂教学或成绩业务 |

三个阶段源于[总体架构](archive/总体架构.md)2.22。后两阶段只有当前记录中实际存在的方向设计，没有被补写成已经批准的详细方案。

## 当前职责边界
用户需求→模型理解/追问/选择工具→后台核验身份、对象、字段、时间→领域查询或预检→明确确认后唯一Writer正式执行→获准真实结果/原回执回模型→继续任务或自然回答。

业务规则不搬进通用内核；模型不能扩大权限、直接操作数据库、代替确认或把未知说成成功。跨学期持续任课、自动计算升年、家校与寄宿关系属于学校事实语义，不是模型猜测。
